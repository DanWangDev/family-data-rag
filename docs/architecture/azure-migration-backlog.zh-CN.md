## 阶段 A：信任边界、基线与选型

- [ ] **AZ-001 / P0：威胁模型与资料分级。** 明确是否接受微软处理敏感资料明文，列出可上传 / 需脱敏 / 保留本地 / 禁止入库的类别。验收：形成可执行的分类规则，覆盖证件、医疗、财务、密码、恢复密钥、照片 EXIF / GPS；明确谁能访问、处理和删除。
- [ ] **AZ-002 / P0：地域、保留与服务资格核对。** 依赖 AZ-001。验收：记录 OCR、模型部署类型、状态存储、监测及备份的处理 / 保存地域与删除方式；复核私网和模型容量支持，未获批的监测豁免不计入承诺。
- [ ] **AZ-003 / P0：建立评测集和本地基线。** 依赖 AZ-001。验收：保存有版本的题目、预期证据、关键字段与评分方式，覆盖无答案、冲突、权限隔离、中英文及统计题；真实资料不进入公共 CI 或 artifacts。
- [ ] **AZ-004 / P0：受控服务对比与总成本模型。** 依赖 AZ-002、AZ-003。验收：比较 OCR / 模型以及 PostgreSQL + pgvector / 可选 AI Search 的质量和成本，计入固定基础设施、私网、VPN、OCR、embedding、重排、模型用量、监控、备份及导出；明确月预算和告警机制。
- [ ] **AZ-005 / P0：定义试点门槛和恢复目标。** 依赖 AZ-003、AZ-004。验收：书面确定关键字段正确率、检索 / 回答 / 引用质量、权限负例、延迟、成本门槛及 RPO / RTO；数值不能以未经批准的默认值代替。

阶段门槛 A：AZ-001～AZ-005 有明确结论后才进入正式试点选型。受控小样本评测需先满足该样本的数据使用与最小安全边界；不得直接全量上传家庭资料。

## 阶段 B：接口、数据与部署基础

- [ ] **AZ-006 / P1：提供商接口与本地适配器。** 依赖 AZ-004。验收：抽离存储、解析 / OCR、embedding、检索、LLM 接口；本地流程继续可用，云目标显式选择、端点严格校验、失败不静默发送至其他供应商。
- [ ] **AZ-007 / P1：标准化 schema 与可追溯元数据。** 依赖 AZ-006。验收：保存原文件哈希、来源、ACL、版本、文本 / 表格、页码 / 区域、置信度、人工纠正及可取得的模型 / API 版本；标准化输出不要求依赖 Azure SDK 才能读取。
- [ ] **AZ-008 / P1：Blob / PostgreSQL 数据迁移与一致性设计。** 依赖 AZ-007。验收：设计有效 run 指针、幂等重试、失败保留旧版、共享内容与来源权限、跨服务发布和回收机制；证明 staging 和未授权内容不会进入查询集合。
- [ ] **AZ-009 / P1：容器与可重复部署配置。** 依赖 AZ-004、AZ-006。验收：本地可构建 API / Worker 镜像，测试环境配置可版本化重建；配置和状态中不含真实家庭资料或明文凭据，依赖和部署说明可复核。
- [ ] **AZ-010 / P1：扩展 CI 与迁移检查。** 依赖相关接口 / schema 任务。验收：在已有 PR / main CI 中增加适配器契约、合成数据迁移、权限负例、生命周期与构建检查；真实环境与真实数据验证独立记录，失败不得合并。

阶段门槛 B：本地可复现接口与数据转换，且必要的合成回归通过。架构图与实现选择同步更新，不把生成器初版当成自动同步的设计来源。

## 阶段 C：测试环境安全边界

- [ ] **AZ-011 / P1：用户和服务身份。** 依赖 AZ-001、AZ-009。验收：MFA、应用登录、Managed Identity 和职责分离配置完成；API、Worker、备份 / 恢复主体仅有必需权限，撤销权限后访问被拒绝。
- [ ] **AZ-012 / P1：VNet、私网与公网关闭。** 依赖 AZ-002、AZ-009。验收：落实应用专用子网、VPN 和各服务独立 PE，明确 PostgreSQL 网络模式；授权 VPN / 应用可访问，而公网客户端无法访问应用与数据服务入口。
- [ ] **AZ-013 / P1：私有 DNS 与受控出站。** 依赖 AZ-012。验收：VPN 和应用解析到预期私有地址；必要平台依赖可用，未批准目的地无法访问；路由 / 防火墙行为有实际验证记录。
- [ ] **AZ-014 / P1：敏感日志、秘密与 CI 访问边界。** 依赖 AZ-011。验收：合成秘密 / 正文注入正常及失败路径后不出现在共享日志 / traces / CI artifacts 中；秘密由受控机制提供，部署身份最小化，备份密钥恢复方式明确。
- [ ] **AZ-015 / P1：文档权限贯穿数据链路。** 依赖 AZ-008、AZ-011。验收：不同成员权限、共享内容去重、来源移除、缓存命中、图谱扩展、重排、LLM 上下文、统计与下载的负例均不越权；授权逻辑不能依赖模型遵守提示词。
- [ ] **AZ-016 / P1：删除、保留和 OCR 临时结果清理。** 依赖 AZ-007、AZ-012。验收：覆盖原文件、派生内容、聊天 / 缓存、服务临时结果与历史版本的策略；OCR 成功保存并校验后清理，失败重试；删除请求与备份保留窗口可追踪。

阶段门槛 C：以上安全验证形成证据后，才允许导入批准的试点资料。私网连通、凭据扫描通过或单一截图均不能替代整条权限与数据流验证。

## 阶段 D：OCR、检索和成本优化

- [ ] **AZ-017 / P1：文档解析 / OCR 路由与字段复核。** 依赖 AZ-003、AZ-007、阶段 C。验收：可靠文本层优先、扫描页 OCR，保留表格与坐标；置信度阈值经样本校准，关键数字 / 日期校验失败可复核；人工纠正不会因重跑丢失。
- [ ] **AZ-018 / P1：可追溯处理缓存。** 依赖 AZ-007、AZ-008。验收：相同内容与处理版本不重复 OCR / embedding，版本变化能够失效；共享缓存不跨越 ACL，重试不重复收费式调用的风险有记录与控制。
- [ ] **AZ-019 / P1：混合检索与多语言质量。** 依赖 AZ-003、AZ-008、AZ-015。验收：比较向量、关键词、融合及重排，验证中文分词、表格与条款召回；候选数量与最终上下文数量独立配置，发布版本和引用一致。
- [ ] **AZ-020 / P1：Token 预算、模型路由和用量记录。** 依赖 AZ-005、AZ-019。验收：使用所选模型实际 token 计量，覆盖系统提示、证据、必要历史和输出预算；普通问题从候选预算起评测，复杂题可扩展；记录升级条件、延迟、用量与正确率，不以模型自报信心代替评测。
- [ ] **AZ-021 / P1：确定性统计和完整证据范围。** 依赖 AZ-008、AZ-015、AZ-017。验收：消费、退款、转账、还款和重复交易规则清晰；月 / 年统计由授权范围内的 SQL / 代码执行并对账，模型解释可追溯，不依靠 top-k 片段估计总额。
- [ ] **AZ-022 / P2：权限感知的查询与对话缓存。** 依赖 AZ-015、AZ-019、AZ-020。验收：ACL、索引 / 文档版本及模型配置变化后失效；包含数字、日期或否定差异的相似问题不错误复用答案；必要历史压缩不改变关键事实。

阶段门槛 D：在 AZ-005 预先约定的质量 / 安全门槛下比较总成本。未达到门槛时定位 OCR、召回、证据选择、生成或数据问题，不能仅通过缩短提示词宣称优化成功。

## 阶段 E：恢复、迁出和切换

- [ ] **AZ-023 / P1：备份与灾难恢复演练。** 依赖 AZ-005、AZ-008、AZ-014、AZ-016。验收：恢复文件、数据库、ACL、有效版本、纠正和密钥，抽查引用与对账结果；满足约定 RPO / RTO，记录恢复时长和未覆盖窗口。
- [ ] **AZ-024 / P1：不依赖 Azure 的迁出演练。** 依赖 AZ-006、AZ-007、AZ-019、AZ-023。验收：导出并校验权威资料，在独立本地环境重建元数据和索引，通过同一评测集；明确更换 embedding 的重算、迁出耗时与流量费用。
- [ ] **AZ-025 / P1：试点双跑、回退与切换。** 依赖阶段 C、D、AZ-023、AZ-024。验收：对批准的小范围数据双跑比对，明确数据写入归属、变更追踪、回退步骤和最终切换条件；失败可恢复到已知可用版本，再决定是否扩大迁移。
- [ ] **AZ-026 / P2：持续运行手册与成本 / 质量复评。** 依赖 AZ-025。验收：覆盖模型退役、配额 / 区域变更、权限审计、预算告警、备份演练、索引重建、API / schema 升级和图文同步；周期和负责人另行确定，不自动创建定时任务。
