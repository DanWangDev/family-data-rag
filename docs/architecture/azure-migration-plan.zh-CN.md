# Azure 迁移设计与决策记录

整理日期：2026-11-20（Europe/London）。状态：规划与评估，尚未部署 Azure 资源、迁移家庭资料或验证云端安全配置。

本文记录本次讨论的目标、设计建议与未决事项，作为后续工作的依据。执行清单见 [Azure 迁移待办](azure-migration-backlog.zh-CN.md)，可编辑架构图见 [架构图与导入说明](README.md)。本地实现与历史验收记录仍保留在项目 README、安全审查和基准文档中；那些记录不构成云端验收结果。

## 目标与决策状态

用户已明确新的方向：从本地方案迁移到 Azure，缓解本地模型算力、向量存储容量与维护、OCR 质量等问题。同时优先考虑家庭资料安全、每个正确答案的成本，以及未来迁往其他平台的能力。

迁移不自动保证 OCR 或 RAG 准确率提升，必须用代表性样本验证。本文中的服务组合、网络拓扑和 token 数值是待评估方案，不代表已批准采购或已满足验收。

| 保留原始资料、证据与人工纠正 | 设计原则 | 云端索引不能成为资料的唯一副本 |

## 当前实现中需要保留的设计

- 原文件按内容哈希保存快照，来源与内容版本分离；允许多个来源引用同一内容。
- 内容与索引构建 run 分离，记录解析、切块和 embedding 的版本信息。
- 通过有效索引指针限定查询集合，失败构建不得覆盖最后可用版本。
- chunk 关联页码、行、段落或 OCR 区域；回答和结构化事实能够追溯来源。
- 人工确认与纠正独立保留，不能被重新抽取覆盖。
- 向量与关键词混合检索；交易对账和金额统计使用 SQL / 代码。

这些是迁移需要维持的业务语义，不意味着 SQLite 特有表结构和事务实现可以直接照搬到云端。对象存储、数据库和可选搜索服务之间的发布、重试与一致性需要重新设计。

## 安全与信任边界

### 服务商明文处理是前提选择

不存在可承诺的“绝对安全”。先确定需要防范的风险，以及哪些主体可以在什么条件下接触资料。

| 要求 | 对方案的影响 |
| --- | --- |
| 防止公开泄露、账户被盗和成员越权 | 使用身份验证、MFA、最小权限、私网、文档 ACL、审计与受控恢复 |
| 不用于训练基础模型 | 核对所选服务、模型来源和具体功能的数据使用条款 |
| 不留存提示词、上传文件或结果 | 逐功能核对状态存储、监测、日志和删除策略，不能从“不训练”推导 |
| 微软也不能接触明文 | 普通托管 OCR、embedding、LLM API 无法满足此目标；客户端加密的密文不能直接用于普通 OCR / 推理 |

Azure OpenAI 的不用于训练承诺，不等于不处理、不留存或不存在受控人工审查路径。滥用监测修改存在资格、审批及模型政策限制，不以个人项目能够获得永久豁免为架构前提。客户管理密钥可增强密钥控制，但不取消普通托管服务执行 OCR / 推理时的明文处理需求。

### 网络边界与托管服务域

网络草案为：家庭设备 / NAS → 加密 VPN → VNet 集成的内部 Container Apps → 独立 Private Endpoint → 托管服务。

- Azure 的 VNet 对应 VPC 概念；Azure 订阅是资源归属与 RBAC 边界，不是网络隔离边界。
- Private Endpoint 位于客户 VNet 内；Blob、OCR、OpenAI、Key Vault 和本图采用 Private Link 模式的 PostgreSQL 仍由微软托管。
- PostgreSQL Private Link 与 VNet 注入是不同网络方案。实施时明确选型，不将两种方式混画或混配。
- 创建 Private Endpoint 后仍需关闭服务公网访问；从公网和允许的私网客户端分别验证。
- Private DNS Zones 关联 VNet，VPN 客户端必须能正确解析服务私有地址；按需配置 DNS 转发 / Resolver。
- VNet 不自动禁止出站。分别设计路由、出站白名单、平台必需依赖及身份 / 管理流量。
- 私网连接不改变服务的数据使用、明文处理、监测或跨地域处理规则。

### 身份、权限与数据生命周期

- 用户启用 MFA；应用使用 Managed Identity 和最小权限。API、Worker、迁移任务及备份任务按职责授权。
- 文档 ACL 必须在检索前执行，覆盖候选召回、图谱扩展、重排、模型上下文、SQL 统计、引用下载与缓存。前端隐藏文件不构成权限隔离。
- 内容去重不合并权限。共享内容的多个来源中，只有用户有权访问的有效来源才能作为引用或下载依据。
- 原文件、OCR 文本、向量、聊天、结构化事实、人工纠正、缓存和备份都按敏感资料保护；向量不视为匿名数据。
- 默认日志不记录正文、提示词、凭据或原始异常；保留必要的资源 ID、错误类别、耗时、用量和审计信息。
- 先定义资料分级与上传规则。密码和恢复密钥不进入 RAG；证件、医疗、财务和照片 EXIF / GPS 按明确策略处理。需要脱敏时，在云服务调用之前执行。
- 定义每类数据的保留、删除和备份到期策略，说明历史版本、日志与备份中的残留窗口。
- Document Intelligence 当前文档说明分析完成后输入和结果暂存 24 小时，可调用删除接口提前清理。保存并校验结果后发起删除，失败可重试并受审计；上线前复核所选 API 行为。
- 不将服务端保存的对话、文件或向量库当成默认选项；按功能明确是否需要及其保留方式。

### 数据驻留

资源区域、VNet 区域、推理处理地域与备份地域分别确认。Global、Data Zone、Standard 等部署类型具有不同的处理范围；资源位于某个区域不代表推理只在该区域发生，也不承诺具体模型在目标地域一定有容量和完整私网能力。

## 准确性与成本设计

目标是降低每个正确、可追溯答案的总成本，同时满足最低质量要求。除输入 / 输出 token，还记录 embedding、重排、OCR 页数、存储、数据库、私网、VPN、计算、监控及导出流量费用；模型的其他计费用量按实际 API 核对。暂不提供未经测量的月费估计。

### 入库时避免重复处理

可靠文本层直接提取；扫描页才 OCR，并校验乱码、阅读顺序、表格、单位和关键数字。按内容哈希与处理版本缓存解析、OCR、抽取和 embedding 结果；内容或版本变化时正确失效。保留原始 OCR 响应、标准化结构、位置、置信度和人工纠正。

关键字段用格式与业务约束校验。低置信度或校验失败的部分进入更强模型或人工复核。OCR 置信度不能直接当成正确概率；模型补全文字也可能产生错误，不能替代原图证据。

### 查询时减少无关上下文

建议路径为：权限与范围过滤 → 向量 / 关键词混合召回 → 重排 → 证据去重与必要邻接补全 → 实际 token 预算 → 带引用回答。

当前 `retrieve.py` 融合向量 top-30 与关键词 top-20 等候选，默认最多返回 12 个片段；`chat.py` 将它们直接组装为提示词。切块按字符数进行，`num_ctx` 不是证据选择的实际 token 预算。迁移时增加预算与计量，不能把字符数等同于 token 数。

- 召回候选数量和最终发送给 LLM 的片段数量分别设置。
- 普通查询可从 2,000～4,000 evidence tokens 开始实验；这不是质量保证或固定上限。复杂问题应按证据完整性扩大范围。
- 去掉重复内容和无关段落，保留表头、单位、否定词、例外、日期与来源。
- 简单任务评估较小模型；复杂或证据不足的任务可升级模型 / 检索范围。升级依据应经过评测，不仅依赖模型自报信心。
- 统计问题使用完整授权范围内的 SQL / 代码计算，处理消费、退款、转账、还款和重复交易，再由模型解释。不能用 top-k 文档近似年度总支出。
- 对话只传入完成当前问题所需的历史或摘要；数字与引用仍回到权威来源。
- 缓存包含权限范围、文档 / 索引版本和模型配置等维度；修改 ACL、删除资料或发布新版本时失效。涉及数字、日期和否定的相似问题不能无条件共用语义缓存。

### 用评测控制质量

建立覆盖中英文、扫描件、照片、表格、长合同、跨文档比较、无答案、来源冲突及权限攻击的样本集。分别测 OCR 关键字段正确率、检索召回、答案正确性、引用支持率、拒答表现、越权泄露、延迟与成本。

真实家庭资料的评测在受控环境运行；CI 使用合成或经过审核的脱敏样本。测试“权限不允许”和“资料不存在”等负例。验收阈值先约定再看结果，不以少数看起来正确的回答替代整体评测。

## 可迁移的数据与代码边界

| 数据层 | 保存内容 | 迁移要求 |
| --- | --- | --- |
| 原始资料 | 原文件、哈希、来源、版本与 ACL | 完整导出、校验哈希、保留授权关系 |
| 标准化资料 | OCR / 表格、位置、事实、纠正与处理元数据 | 项目自己的 schema；独立于 Azure 响应格式可读取 |
| 派生索引 | chunks、向量、全文索引、构建 run / generation | 可以重建；记录来源与构建配置 |

优先评估 Blob 保存文件、PostgreSQL 保存元数据与关系数据、pgvector 保存向量的组合。中文关键词检索需验证分词和索引策略，不能假设 PostgreSQL 默认全文检索与现有 jieba 行为等价。Azure AI Search 可作为候选实现，其索引不能成为唯一权威资料。

建立少量项目自有接口：`ObjectStore`、`DocumentParser` / OCR、`Embedder`、`Retriever` / Search、`LLM`。Azure SDK 与响应转换集中到适配层；业务流程不依赖 Azure Portal 中无法导出重建的配置。保留本地适配器作为评测和回退路径，不通过放开现有 Ollama 本地限制来增加云能力；云提供商须显式选择并校验目的地，禁止静默跨供应商回退。

记录供应商、部署 / 模型标识、可获得的实际模型版本、API 版本、解析 / 切块 / 标准化 schema 版本、向量维度和配置指纹。云模型未暴露本地式权重 digest 时记录可取得的标识，不伪造可重现性。

相同向量维度不代表模型空间兼容。更换 embedding 模型通常需要重新生成文档向量；接口兼容也不代表结构化输出、引用与拒答行为一致。容器和基础设施代码提高可重复性，不承诺跨云一键迁移。

最终迁移能力的验收是：在不依赖 Azure 的环境中，用导出的原始和标准化资料重建数据库 / 索引，并通过同一评测集。恢复必须覆盖权限、纠正、引用和密钥恢复，不仅检查文件数量。

## 实施顺序与变更范围

1. 确认安全信任、资料分级和允许的地域；建立本地质量 / 成本基线。
2. 用受控的小样本评估 OCR、模型、检索候选与服务总成本，确定生产前的验收标准。
3. 拆出适配接口和标准化 schema，保留本地路径；设计云端一致性与发布语义。
4. 在隔离的测试环境验证身份、VNet、私网、DNS、出站和日志边界，再处理经批准的试点资料。
5. 迁移数据与检索，逐项验证权限、生命周期、恢复和迁出能力，通过质量门槛后扩大范围。
6. 明确回退流程和最终切换条件；未通过验收时保留现有可用路径。
